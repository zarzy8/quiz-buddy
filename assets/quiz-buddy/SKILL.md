# quiz-buddy · 复习资料 / 题库双模式

## 流程总览

1. 读文件（读不到就说读不到）
2. 问类型：复习资料 还是 题库
3. 复习资料 → 问：总结要点并出题 / 只出题；题库 → 直接开始
4. 用答题卡片逐题作答
5. 结算：总题数、错题数、准确率、错题题目 + 你的答案 + 正确答案 + 解析

## 0. 读文件（不猜内容）

1. 从用户消息取路径：`@路径`、附件路径、或对话里给的绝对/相对路径。没有路径就只问一句文件位置。
2. 按扩展名读取：
   - `.md` `.txt` `.csv` `.json` `.html`：read 工具直接读；超过 2000 行分段读完。
   - `.docx` `.pptx` `.xlsx` `.pdf`：先加载 `office` 技能，再按说明抽取文本。
   - 其他格式：说明无法解析，请用户转成文本/Markdown。
3. 读不到（扫描版 PDF 无文字层、图片、加密）：直接说"这份文件没有可提取的文字"，请用户给文字版。**禁止凭标题编造内容。**
4. 多个文件：逐个确认用途，再统一处理。

## 1. 必问：复习资料还是题库

读完文件后先给一行判断和依据，例如：
`读完像是复习资料：有 6 个章节的讲义，没有成组选项和答案。`

然后**明确问一次**：

> 这份文件是「复习资料」还是「题库」？

可用 ask_user_question（两个选项）；环境不支持就用纯文本。用户不回答就按你的判断继续。
即使文件看起来很明显，这一步也不要省——用户最清楚文件性质。

判定参考（只用于给你的判断，不替代提问）：

| 信号 | 倾向 |
|---|---|
| 连续编号题干 + A/B/C/D 选项，或【答案】/解析/分值/题型分区 | 题库 |
| 章节标题 + 成段讲义、定义、公式，无成组选项 | 复习资料 |

## 2. 复习资料分支：再问一次

用户确认是复习资料后，问一次：

> 你需要「总结要点并出题」，还是「只出题」？

- **总结要点并出题**：先给要点（按原文章节分组，保留定义、公式、数字阈值、易混点，标原文位置），再开始出题。
- **只出题**：不给长篇总结，直接进入出题。

只出题时必须**完全掌握文件内容**再动笔：

- 逐章/逐页读完，不允许只读开头就出题；
- 内部建立题源清单：每章的概念、公式、数字、易错点各列几条，确保出题有出处；
- 题目覆盖全部章节，不得反复考同一段；
- 答案与解析以文件内容为准，文件没说的一律标"补充"。

## 3. 题库分支：直接开始

用户确认是题库后，不再问总结还是只出题，解析题目后直接进入答题卡片。

解析规则：

- 每题保留：序号、题型、题干、选项、答案、解析、知识点。
- 缺答案：标"原题未给答案"，按知识作答并注明"自判"。
- 答案与解析冲突：以标注答案为准，并指出冲突。
- 还原不了的题（跨页、乱码、选项错位）：标"待人工确认"，不硬猜。
- 只收单项选择题、多项选择题、判断题；简答题、程序与命令题、综合设计与应用题**暂不支持**——跳过，并在开始时说明跳过了多少道、各是什么题型。

## 4. 答题卡片（小程序式界面）

出题时不要用纯文字罗列，**一次一题弹一张答题卡片**，界面为：

```
1. [单选题] 题干？
  (A) 选项一
  (B) 选项二
  (C) 选项三
  (D) 选项四
```

- 卡片模板：`assets/question-card.json`，读取后替换 `state.q`（题号、题型、题干、选项、答案、解析）。
- 用 TinyCard 包裹；选项用纵向 TinyRadioGroup（圆形单选标记 + 选项文字），多选题用 TinyCheckboxGroup，判断题给「对 / 错」两个选项。
- 点击选项即提交：卡片方法 `pick(value)` 调用 `this.callAction('continueChat', { message: '第 N 题我选 X' })`，模型收到后判分、记分，并弹下一张卡片。
- 下一张卡片**顶部**先给上一题反馈（对/错、正确答案、解析），再显示新题目，底部保留进度「第 N / 共 M · 已答 · 对 X」。
- 多选题用 TinyCheckboxGroup，选项确认后才提交；判断题给「正确 / 错误」两个选项。
- 卡片里永远不提前显示答案；只有判分后才显示解析。
- 环境不支持交互卡片、或卡片发了没显示时：改用 §6 独立窗口模式，不要退回纯文字罗列。

## 5. 记分与结算

模型在对话中维护：总题数、已答题数、正确数、错题列表（题号、题干、你的答案、正确答案、解析、知识点）。

答完全部题目或用户说"结束/退出"时，**必须给出**：

1. 总题数
2. 错题数
3. 准确率 = 正确数 ÷ 已答数（保留整数百分比，并写明"已答 X / 共 Y"）
4. 错题清单：逐条列出**题目、你的答案、正确答案、解析**
5. 薄弱知识点 top 3 与复习建议

结算卡片模板：`assets/result-card.json`（顶部三行统计，下方表格列错题）。卡片放不下全部错题时，只放前 5 条并注明"其余见对话"，然后在正文补全。

## 6. 独立窗口模式（卡片不显示时）

聊天内嵌卡片在部分客户端不会渲染。用户要"弹窗 / 小程序"，或卡片明明发了却没出现时，改用本地网页版：

1. 建 `quiz-app/`，从本技能所在目录的 `webapp/` 复制 `server.py`、`index.html`；再生成 `questions.json`。
   - 字段：`id`、`type`、`no`、`stem`、`options[{label,text}]`、`answer`。
   - `answer` 只留在题库文件里，服务端判分，客户端拿不到。
   - 同一题号跨题型要加前缀（如 `S-1`、`M-1`、`J-1`）。
2. 后台启动：`python -u quiz-app/server.py 8777 quiz-app/questions.json quiz-app/answers.jsonl`；确认 `http://127.0.0.1:8777/api/questions` 返回 200。
3. 开窗口：`Start-Process <msedge 路径> --app=http://127.0.0.1:8777/ --window-size=780,940`；没有 Edge/Chrome 就直接打开该 URL。
4. 窗口内点选项即判分，答案实时写入 `quiz-app/answers.jsonl`。用户说"统计 / 答完了"时读该文件，按 §5 输出总题数、错题数、准确率与错题清单。
5. 端口占用就换 8778 起；服务需保持后台运行，关掉会话即停。

## 7. 共用规则

- 语言跟随材料；术语首次出现给英文原文。
- 不泄题：出题阶段任何输出（含卡片）都不能包含答案。
- 不编造题目来源、页码、分值；不确定标"未标注"。
- 交互克制：每个分支只问一次，用户说"直接开始"就按默认值走。
- 结束前自检：每题答案有出处吗？覆盖全部章节吗？统计数字和错题列表对得上吗？
